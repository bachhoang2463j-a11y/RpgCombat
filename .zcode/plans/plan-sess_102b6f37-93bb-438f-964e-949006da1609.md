## 目标
新增两个我方英雄标签（敌方不改）：
- **`[延迟:N]`**：技能先"蓄力"N 回合（该英雄的名字称作"蓄力中"），**蓄力期间只处于准备态，不结算任何技能效果**；蓄力完成后才释放该技能、触发其全部效果（含自身携带的 `[加速:N]`）。
- **`[加速:N]`**：永久加速库存（不自动过期）。只在**蓄力结算完成时**才施加到角色身上。之后每次蓄力按"所需延迟回合"抵扣库存：蓄力3 遇 加速9 → 加速变6。

> 顺序：**先蓄力 → 完成后结算（此时才+加速）**。因此 `[延迟:3][加速:3]` 第一次要蓄力3回合，完成时+3加速；**下一次**再使用，库存3 抵扣 蓄力3 → 立即释放（"持续射击"）。加速永远不影响"本次这一次"，只影响"之后"。

## 标签说明 / 冲突
- 新机制用 **`[延迟:N]`**（你已确认，避免与敌方 `[蓄力]` FGO 大招充能槽冲突）。
- **`[加速:N]`** 直接使用。你的示例 `[蓄力:3][加速:3]` 在引擎中即 **`[延迟:3][加速:3]`**。

## 核心机制
- **数据字段**（英雄对象）：
  - `hero.hasteStore`（数字，默认0）：永久加速库存，UI 显示 `⚡加速xN`。
  - `hero.currentDelay = { skill, remaining }` 或 null：当前蓄力中技能。
- **施放 `[延迟:N]` 技能**（每回合该英雄只能起手一个蓄力）：
  1. 用当前 `hasteStore` 抵扣：`covered = min(delay, hasteStore)`；`hasteStore -= covered`；`effective = delay - covered`。
  2. `effective == 0` → 立即释放（本回合）。
  3. `effective > 0` → `currentDelay = { skill: {...skill, haste:0}, remaining: effective }`，本回合结束。
- **蓄力期间**：该英雄**不能主动行动**（普攻/技能/防御禁用），但**反应与看破照常可用**（`promptReaction`/`promptKanpo` 代码不改，天然可用）。
- **蓄力完成时**（该英雄下一次行动，`remaining` 归零）：
  - 释放该技能 → 走 `executeSkillAction` 触发全部效果，**此时才施加 `skill.haste`**（`hasteStore += skill.haste`，用原技能副本）。
  - 如有 `[再动]` 等标签照常联动。
- **每回合推进**：仅在该英雄**非额外行动**（`!isExtraTurn`，与 Buff 计时同处 line 5507）时 `remaining--`。

## 实现步骤（全部在 `战斗前端-爬塔 V5.2.html`）

### 1. 解析 `parseSkill`（line 3443）
- 新增 `[延迟:(\d+)]` → `skill.delay`；`[加速:(\d+)]` → `skill.haste`（`|| 0`）。
- 返回对象（line 3501）追加 `delay, haste`。

### 2. 技能编辑器（我方）
- 我方技能行（line 6157）"回数"旁新增：`延迟(蓄力)`→`edit-h-…-delay`、`加速`→`edit-h-…-haste`。
- `syncEditorDataToMemory`（hero 分支 line 6189）读取两者。
- `addHeroSkill`（line 6288）默认 `delay:0, haste:0`。

### 3. 持久化
- `serializeHeroesForSave`（line 6412）技能映射追加 `delay, haste`；`applyPersistedRoster` 无需改（无字段按 undefined 兜底）。

### 4. 施放入口（蓄力拦截）
- 新增 `handleChargeSkill(hero, skillIndex)`：
  - 用副本 `{...skill, haste:0}` 计算 effective（避免本轮重复加加速）。
  - effective>0 → 写 `currentDelay`，显示蓄力徽章，`endTurn`。
  - effective==0 → 立即 `executeSkillAction` 释放（自动选目标：有益给自己 / 敌方单体随机存活敌人 / 群攻按 executeSkillAction）。
- `prepareSkillTarget`（line 5879）开头：`if (skill.delay > 0) { handleChargeSkill(...); return; }`。
- `updateMenu`（line 6037）：`hero.currentDelay` 存在 → 只渲染"⏳蓄力中"占位，不渲染技能按钮。
- `actionDefend`（line 6026）、`prepareAttack`：蓄力中守卫。

### 5. 回合推进与自动释放（`nextTurn` line 5489）
- `!isExtraTurn` 区块（line 5507）新增：英雄且有 `currentDelay` → `remaining--`；归零 → `currentDelay=null` 并自动释放（apply 原技能含 `skill.haste` → `hasteStore += skill.haste`，还原"完成才加速"）→ `endTurn`；未归零 → 显示蓄力、`endTurn`。
- 英雄死亡清空 `currentDelay`。

### 6. Buff UI（`updateBuffUI` line 3674）
- `currentDelay` → `⏳蓄力{remaining}` 徽章。
- `hasteStore > 0` → `⚡加速x{hasteStore}` 徽章。

- `README.md`、`SPEC.md`、`LOG-INDEX.md`、`LOG.md` 补 `[延迟]`/`[加速]` 说明与施工记录。

## 验证
- Node 提取 `<script>` syntax 校验零报错。
- 手操实测：`[延迟:1]` 占2回合且释放时才结算；`[延迟:3][加速:9]` → 蓄力期间库存9→...→释放后库存9-3=6（本次不受加速影响）；`[延迟:3][加速:3]` → 第一次蓄力3回合，完成+3库存，**第二次**才立即释放；蓄力期间可反应/看破、不可主动行动。

## 备注
- 敌方 `[Charge]/[充能]/[蓄力]` 大招充能槽**完全不动**。
- 蓄力中自动释放的对敌单体目标采用"随机存活敌人"。
