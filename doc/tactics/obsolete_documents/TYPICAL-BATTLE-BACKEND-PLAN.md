# 典型对局 · 战棋版后端实施计划（TYPICAL-BATTLE-BACKEND-PLAN）

> 状态：权威文档与后端阶段1—7已接线，相关测试已运行；最终全量与单文件专项见本轮验证报告。前端模型接线后的权威典型战局页面验收尚待完成，不能称正式版已通过。
> 配套文件：[典型对局-战棋版.yaml](../典型对局-战棋版.yaml)（权威样本）、[TYPICAL-BATTLE-CONTRACT.md](../TYPICAL-BATTLE-CONTRACT.md)（交接契约）。

## 核心目的

以《典型对局-战棋版.yaml》为唯一权威样本，驱动战棋后端把「4 英雄 vs 6 敌 + 2 召唤模板」的典型对局在 sc-chapel 场景完整跑通；同时把样本涉及的规则增量（位移标签扩展、冲撞、浓雾、免伤整技池、跳跃新公式、召唤道具入场、资源基线）落入生产实现，并用测试与单文件产物验收闭环。

## 具体任务（阶段）

每阶段完成后用一句话复述「目的 vs 现状」是否仍一致；偏离即停，先向用户呈报。

### 阶段 1：权威样本（已完成）
- 产出 `doc/tactics/典型对局-战棋版.yaml`（4 英雄 / 6 敌 A·B 展开 / 2 召唤模板 / meta 站位与决策记录）与本文档、契约文档。
- 完成判据：YAML 经 js-yaml 解析通过；单位与站位数量核对一致；共识条目逐条落档（见契约第三~十三节）。

### 阶段 2：生产数据 / 交接契约
- 按契约第二节把样本字段映射到 `parser.mjs` / `protocol.mjs` 生产结构（P01 字段冻结补充：中文字段映射、特性→attrTags、行动次数忽略、父子物品共享次数）。
- 复用现存编译链，不另造第二套解析。
- 验收：样本可编译为 compiled 配置，站位与 footprint 正确（2×2 左上格锚点）。

### 阶段 3：行动与状态
- 全员跳距ceil(基础移动/3)、耗辅一次、不扣移动；飞行移动+50%、跨低障碍；TP全0、充能获TP；持久状态默认3回合，无迹可寻2回合，护盾累计保留，眩晕无power。
- 验收：相关单测覆盖上述时效与资源行为。

### 阶段 4：逐段防护
- 免伤整技池（护甲→池→盾→HP；同源替换；整技结束清除）；逐段反应重用扣费；单避化解本段；后续段原目标合法性重查。
- 验收：多段技能（三连发、归尘礼赞延迟段、维度撕裂）逐段反应链单测。

### 阶段 5：冲锋
- 冲撞：直线 6m 宽 2m 自身冲锋、每目标一次、沿冲锋方向击退 3、撞开继续、墙/友军阻挡、失能收口（契约第六节）。
- 验收：位移原语（`movement.mjs traceDisplacement` 复用扩展）+ 冲撞专项单测。

### 阶段 6：浓雾感知 AI
- 显式雾区配置（不按技能名判断）、进入即致盲/离开解除、同源替换、雾区最高值、其他致盲原版叠、雾内八邻域可见按大型边缘、雾外视距不减、AI 无贴身优先离雾可冲刺出去再攻击。
- 验收：雾区视野与 AI 决策专项单测。

### 阶段 7：召唤物品结界
- 召唤仅经道具入场（父瓶 1 次两子共享、父音叉 3 次三子共享、钥匙去增防）；召唤物模板实例化与归零死亡；结界按 SPEC S07 复用现有耐久/拦截工具。
- 验收：召唤入场、次数共享、结界拦截相关测试。

### 阶段 8：测试节奏
- 开发期间只跑改动影响范围内的相关测试；全部相关测试通过且代码稳定后，**打包前统一跑唯一一次全量回归**；打包后仅跑产物专项断言与本轮相关产物回归；源码与产物不重复跑全量（AGENTS.md 第六条）。

### 阶段 9：前端模型接线后单文件产物真页验收
- 由当前源码重跑 `node tactics/tools/build-demo-html.cjs` 产出 `tactics/mvp-standalone.html`；跑产物专项断言（关键模块入包、零外部 import、脚本闭合标签数）；真实页面至少一条完整战斗流程交互验证（AGENTS.md 第七条门禁）。
- 边界：前端 `main` / UI / 导演特效另有模型负责，本计划不动；现存函数复用，不重复造轮子。
