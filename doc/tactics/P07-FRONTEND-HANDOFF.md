## 确认的问题与证据

### P0：菜单空间挤压与物品入口裁切

原版菜单保持 `260×172` 与 `overflow:hidden`，新增余额与动作工具区却插进同一固定容器。2026-11-22 IAB 当前单文件页面、1280×720 的实际元素边界：

- `#menu-container`：x=1008、y=498、width=260、height=172，底边 y=670。
- `#main-menu`：y≈571.7、height≈141.3，底边超过容器。
- “🎒 物品道具”按钮：y≈677.7、height≈29.3，整枚按钮位于裁切区之外。

这是页面 DOM 边界实测，不是仅根据源码猜测。截图调用发生一次 30 秒超时，因此本轮不声称已有成功截图或真 Chrome 视觉验收。此前 LOG 的标题/结束按钮不可见记录与本轮物品裁切分开保留，不推断每种子菜单均具有完全相同的裁切位置。

### P1：动作入口与技能状态难理解

冲刺、跳跃、推动、背起、放下、准备、取消蓄力与余额挤在技能菜单中。部分操作立即执行，部分还需地图选目标，状态表达不足。规则已返回详细中文禁用原因，但技能卡主要依靠悬停 title，触屏或直接浏览难发现原因。

### P1：未迁移功能与可用入口混淆

物品仍不可执行；防御姿态与撤离未迁移；看破/舍身、召唤、治疗与通用恢复等边界见 P07-MIGRATION.md。不能在视觉改造中让这些入口看似已具备效果，也不能因为卡片绘制成功就放开资格。

### P1：角色编辑器日常使用成本

当前技能/物品使用 JSON 文本，属性与持久开关集中平铺，适合规则测试但不适合日常配置。保存按钮的“保存并重置本场”语义、本场 HP/MP 与敌方仅内存、YAML 显式字段优先等规则必须保持清晰。编辑器功能已存在，不要误判为需从零开发。

### P1：保存后敌方头像显示退化（本轮页面观察）

仅编辑玛德琳技能并保存重置后，四个敌方原有 emoji 变为“头像缺失”，行动轴显示幽灵占位。需核对 editorOverrides 的 displayName 与 emoji 解析，不能将纯技能编辑变成敌方显示身份变化。本轮不改动该既有编辑器路径。

### P2：验证债与样式维护

六范围形状、复杂状态、敌方行为均需逐场景补页面验证。tactics.css 中行动余额/工具样式有重复定义，属于既有问题；清理应在前端轮结合真实表现验证，不在规则轮顺手处理。IAB 后台动画/截图与完整 Chrome 调度不同，不能为 IAB 独有现象过度修改产品。

## 给下一轮模型的修改目标（不限定改法）

1. **消灭菜单裁切**：1280×720 与 1600×900，默认菜单及攻击/辅助/物品子菜单的有效内容和导航可见可点；结束回合不能只有键盘入口，Space 保留为快捷键即可。技能首尾与物品入口不被动作工具区挤出。
2. **让动作资源和流程一眼可懂**：明确剩余移动/主点/辅助点，区别立即执行、地图选目标与不可用；准备与取消只在相应状态提供，满准备释放/取消流程可理解。
3. **让禁用理由可读**：无需悬停也能知道冷却、限次、资源、准备状态或尚未迁移等原因，不遮挡技能名字、数值与范围；键盘和触屏能使用。
4. **诚实表达未迁移能力**：明确物品、防御、撤离等入口状态，反馈足够持久；不得放开 skillSupport 或用演出伪造数值效果。
5. **降低角色配置门槛**：日常改名、属性、HP/MP、持久项及技能/物品配置更易操作，保留高级 JSON 能力与精确错误定位；不改变白名单、存档与本场重置规则。
6. **发挥整体视觉与信息设计**：在上述问题和操作验收满足的前提下，自主提升层次、空间、动效和战术可读性，不要求保持现有工具按钮堆叠形式。
7. **补页面验收**：六范围分别核对预览和实际命中；正常、禁用、准备中、满准备、倒地、敌方回合分别验证；真 Chrome 布局/调度验收须先获用户排障授权。
