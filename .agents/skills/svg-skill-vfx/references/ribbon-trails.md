# 世界坐标拖尾

制作刀刃残影、箭尾或冲刺丝带时读取；不把普通粒子爆散默认升级为新的拖尾系统。

## 范围与现有能力

这是拖尾设计与坐标语义参考，不是已实现的 ribbon 网格算法。
项目路径均相对仓库根目录：

- `tactics/src/vfx-primitives.mjs` 已有 DOM + WAAPI 粒子，以及沿固定贝塞尔路径推进的 SVG `trail()`。
- `tactics/src/vendor/rpg-av/rpg-av.mjs` 已有 Canvas 粒子底座。不能只看局部 DOM 原语就断言项目没有 Canvas 或必须升级渲染器。
- 固定路径上的一段光轨，与根据实际运动历史生成的动态拖尾，是不同能力；按本轮效果选择，不同时重做两套。

## 先确定坐标语义

| 表现要求 | 历史点的语义 |
|---|---|
| 箭矢、冲刺经过后留下痕迹 | 采样时记录世界美术坐标，历史点不再随发射者移动 |
| 始终贴着武器或角色的局部残影 | 明确使用局部坐标，并让同一父层承担整体变换 |
| 镜头移动时轨迹仍留在原位置 | 数据保持世界美术坐标，镜头只变换共同父层 |

`vfx-host.mjs` 的 `pointOf()`、`rectOf()` 与 world-root 子层提供项目坐标契约。不要把 `getBoundingClientRect()` 的屏幕结果直接塞入世界历史点，也不要给历史点再次施加相机平移缩放。

melonJS 的 `referenceSpace: "world"` 指相对发射器所在容器；它不是对所有引擎都通用的绝对世界坐标定义，更不是 ribbon 几何算法。项目应使用自身宿主的坐标语义，不引入该配置 API。

## 拖尾构型与采样思路

以下是待具体实现和验证的设计步骤，不是外部技能交付的可复制代码：

- 记录位置和演出时间，按实际运动距离与曲率决定采样方式；不要把每帧采一个点当成跨帧率都一致的保证。
- 用历史点的年龄决定宽度、颜色和透明度衰减。归一化生命周期只是表达方式，不意味着对象池、更新或回收算法已经存在。
- 丝带需由中心线切向与法向确定两侧边界，再连接为连续轮廓；顶点生成、转弯连接和重复点处理仍需具体算法及验证。
- 若要表现真实刀刃扫掠面，考虑记录刀根和刀尖的运动边界；不要把中心线加粗直接称为完整刃面。
- 轮廓遵守主技能的柔边、渐变与辉光要求，不以硬边线框代替最终效果。
- 闪现、消失后现身或重开时按动作边界断开历史，避免把两段不连续的运动连成长条。

## 接入与验证

- 复用现有 Canvas/SVG 宿主、演出时间与作用域清场；不要新建独立渲染引擎或永久帧循环。
- 先验证直行、转弯和速度变化，再检查镜头移动、倍速切换、动作中断与重开是否留痕。
- 粒子数量、历史长度和更新频率由本轮视觉需求及测量决定；没有性能实测时，不声称当前 DOM 性能够用，也不预设未经确认的升级门槛。
